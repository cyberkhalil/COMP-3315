الجزء الأول: أسئلة موضوعية — 20 درجة

يتألف من 8 أسئلة اختيار من متعدد (MCQ) كل سؤال بقيمة 2 درجتين = 16 درجة، و4 أسئلة صح/خطأ True/False كل سؤال بقيمة 1 درجة = 4 درجات. (ملاحظة: أسئلة الفصل الثالث Chapter 3 تُمثّل 10% من الامتحان الكلي = 6 درجات — لذلك 3 أسئلة MCQ من Chapter 3 بقيمة 2 درجتين لكلٍ).

  1. م1 (2 درجتان) — Chapter 3 (Transport Layer)

    في بروتوكول التحكم بالنقل مثل TCP، أيّ العبارات التالية صحيح بخصوص آلية Selective Repeat مقارنة بـ Go-Back-N؟

    1. Selective Repeat يعيد إرسال كافة الحزم من أول خطأ حتى الآن بينما Go-Back-N يعيد إرسال الحزمة الخاطئة فقط.
    2. Selective Repeat يسمح بمؤشرات نافذة مستقلة على المرسل والمستقبل (sender/receiver window) ويعيد إرسال الحزم المتأثرة فقط، بينما Go-Back-N يعيد إرسال نافذة كاملة بعد فقد حزمة.
    3. كلاهما لا يستخدم ACKs تراكمية (Cumulative ACKs).
    4. Go-Back-N يتطلب ذاكرة أكبر في المستقبل مقارنة بـ Selective Repeat لمعالجة الحزم خارج الترتيب.

    اختر الإجابة الصحيحة: A / B / C / D

  2. م2 (2 درجتان) — Chapter 3 (Transport Layer)

    أيّ وصف أدناه يميّز ACKs تراكمية (Cumulative ACKs) عن ACKs لكل حزمة (Per-packet ACK)?

    1. Cumulative ACK يؤكّد استلام آخر بايت متتابع دون الحاجة لتقرير عن كل حزمة منفصلة، بينما Per-packet ACK يؤكّد كل حزمة فرديًّا.
    2. Per-packet ACK يتضمن عادة رقم نافذة (window) بينما Cumulative ACK لا يفعل ذلك.
    3. Cumulative ACK لا يمكنه أن يغطي إعادة الإرسال Selective Repeat.
    4. لا يوجد فرق عملي بينهما على مستوى TCP.

    اختر الإجابة الصحيحة: A / B / C / D

  3. م3 (2 درجتان) — Chapter 3 (Transport Layer)

    في سياق Socket Programming، أيّ من العبارات التالية صحيحة عادةً بالنسبة لبنية Socket في TCP؟

    1. Socket يُعرَّف بزوج (IP address, Port) ويُستخدم لتشكيل اتصال مُوجّه وقائم على الحالة (connection-oriented).
    2. Socket في TCP لا يحتاج إلى Port لأن الاتصال يتم بواسطة IP فقط.
    3. Socket يمنع تقسيم البيانات إلىSegments — هذه وظيفة طبقة الشبكة فقط.
    4. Socket و UDP هما نفس الشيء من حيث ضمان الاستلام.

    اختر الإجابة الصحيحة: A / B / C / D

  5. م5 (2 درجتان) — Chapter 4 (Network Layer)

    عند مقارنة IPv4 و IPv6، أيّ من التالي صحيح بخصوص عملية التجزئة (fragmentation)?

    1. IPv6 يسمح للمراسل (source) فقط بتجزئة الحزم، بينما IPv4 يمكن للمسار (intermediate routers) تجزئتها أيضاً.
    2. IPv4 لا يدعم التجزئة على الإطلاق.
    3. IPv6 يعتمد على حقل Flags في header لتنفيذ fragmentation بالطريقة نفسها في IPv4.
    4. كلا البروتوكولين يسمحان للتوجيهات (routers) بتجزيء الحزم دائمًا.
  6. م6 (2 درجتان) — Chapter 5 (Control Plane / ICMP)

    أداة traceroute غالباً ما تستخدم رسائل ICMP أو UDP مع TTL متزايد. أيّ وصف أدناه يشرح لماذا traceroute يتلقى رسائل "Time Exceeded" من الموجّه (router)؟

    1. لأن الموجّه تجاوز حجم الـ MTU ويعيد التجزئة باستخدام ICMP Message.
    2. لأن الـ TTL (Time To Live) للباكيت وصل إلى صفر عند الموجّه، والموجّه يرسل رسالة ICMP Type 11 (Time Exceeded).
    3. لأن اتصال الـ TCP أغلق فجأة ويولّد الموجّه رسالة Time Exceeded.
    4. لأن عنوان الوجهة خاطئ، والموجّه يرسل دائمًا Time Exceeded بدلًا من Destination Unreachable.
  7. م7 (2 درجتان) — Chapter 6 (Data Link)

    في بروتوكول ARP، عندما يريد مضيف معرفة MAC لـ IP داخل نفس الشبكة المحلية، ما الذي يحدث عادة؟

    1. يُرسل المضيف ARP Request كبث (broadcast) على عنوان MAC العام (FF:FF:FF:FF:FF:FF) و ينتظر ARP Reply من صاحب العنوان.
    2. يُرسل المضيف الحزمة مباشرة إلى Switch لأن Switch يحفظ كل عناوين الـ IP إلى MAC mapping دائمًا.
    3. يُستخدم بروتوكول DHCP للعثور على MAC مقابل IP.
    4. يُرسل المضيف الرسالة عبر الإنترنت إلى الـ Gateway فقط (unicast).

صح / خطأ — 4 أسئلة (كل سؤال 1 درجة)

  1. ص/خ: عنوان الـ Broadcast في Ethernet هو FF:FF:FF:FF:FF:FF. (صحيح / خطأ)
  2. ص/خ: NAT يغيّر header طبقة النقل (TCP/UDP ports) دائمًا عند ترجمة عنوان IP. (صحيح / خطأ)
  3. ص/خ: في Longest Prefix Match، الإدخال ذو أقصر طول prefix له الأولوية. (صحيح / خطأ)
  4. ص/خ: CRC يُستخدم للكشف عن الأخطاء في إطار Data Link ويكشف كل حالات الخطأ المحتملة دائماً. (صحيح / خطأ)

الجزء الثاني: أسئلة مقالية وتحليلية — 40 درجة

5 أسئلة مقالية مركزة. أجب عن كل سؤال بإيجاز ومباشرة مع توضيح الحُجج، الرسوم التوضيحية البسيطة، والحسابات المطلوبة. اذكر النقاط الرئيسية ودرجة كل جزء وفق مقياس التصحيح المرفق.

  1. س1 (8 درجات) — IPv4 vs IPv6 (Compare & Analyse)

    قارن بين IPv4 و IPv6 من النواحي التالية: (أ) مساحة العنوان والعناوين الاختيارية (addressing), (ب) التجزئة (fragmentation) ومن يقوم بها، (ج) وجود NAT والحاجة إليه، (د) اختلافات في header (ماذا أثر ذلك على processing في routers).

    التقييم: كل جزء فرعي (أ–د) 2 درجة: ذكر الحقائق الصحيحة (1d)، شرح أثرها العملي/تصميمي (1d).

  2. س2 (8 درجات) — Longest Prefix Matching & Routing Table (Apply)

    أمامك جدول توجيه موجز. اعرض كيفية اختيار الـ next-hop لوجهاتٍ مختلفة، واشرح لماذا تُطبق قاعدة Longest Prefix Match. اشرح أيضاً كيف يؤثر وجود Default Route (0.0.0.0/0) على القرار.

    Routing table (example):
    - 10.0.0.0/8 → Next-hop A
    - 10.10.0.0/16 → Next-hop B
    - 10.10.5.0/24 → Next-hop C
    - 0.0.0.0/0 → Next-hop D (default)

    أجب: ما هو next-hop للحزم الموجهة إلى 10.10.5.129 ، 10.10.8.7 ، 10.20.1.1 ؟ شرح موجز مطلوب.

    التقييم: تفسير الاختيارات الصحيحة لكل وجهة (2x3 = 6 درجات) + شرح دور Default Route وتطبيق Longest Prefix Match (2 درجات).

  3. س3 (8 درجات) — Routing Algorithms & Protocols (Analyse & Compare)

    (أ) قارن بين خوارزميات التوجيه Link State و Distance Vector من حيث: معلومات الحالة المطلوبة، سرعة التوصّل إلى تقارب (convergence), مقاومة حلقات التوجيه (routing loops). (ب) قارن بين OSPF و BGP من حيث المستوى العملي (intra-domain vs inter-domain)، ومبدأ تبادل المعلومات، وكيفية اتخاذ قرارات المسار (path selection).

    التقييم: كل قسم (أ) و (ب) 4 درجات — نقاط المقارنة الأساسية (2) + أمثلة/شرح عملي (2).

  4. س4 (6 درجات) — Subnetting (Problem Solving)

    لديك شبكة 192.168.100.0/24. مطلوب تقسيمها إلى ثلاثة شبكات فرعية تستقبل على الأقل: 100 مضيف، 50 مضيف، 20 مضيف على الترتيب. اعطِ لكل شبكة: شبكة الشبكة (network address)، قناع الشبكة (subnet mask)، ونطاق عناوين المضيفين (usable host range). اذكر طريقة حسابك بإيجاز.

    التقييم: كل شبكة صحيحة = 2 درجات (الإجمالي 6 درجات). تُمنح نقاط جزئية لحساب صحيح وقناع مناسب.

  5. س5 (10 درجات) — سؤال تجميعي شامل (Synthesis): تتبع مسار طلب ويب (Web Request)

    سيناريو: جهاز كمبيوتر العميل (Client) لديه عنوان IP محلي 10.0.1.10/24 وMAC = AA:AA:AA:AA:AA:01 ويريد إرسال HTTP request إلى خادم على الإنترنت عنوانه الظاهر 198.51.100.25. شبكة العميل متصلة إلى Router (NAT) الذي يمتلك IP داخلي 10.0.1.1 وIP خارجي 203.0.113.5. شبكة الإنترنت تحتوي على عدة راوترات وSwitches وصولاً إلى الخادم. تفترض أن الخادم عنوان MAC وجهته معروف عند الشبكة الطرفية للخادم.

    اطلب من الطالب أن يشرح خطوة بخطوة (موجز لكن محدد) دورة حياة هذا الطلب على المستويات التالية: Application → Transport → Network → Data Link → Physical، مع التركيز على طبقتي Network و Data Link: كيف تُحوّل العناوين (IP, MAC)، متى يُستخدم ARP، ماذا يحدث عند NAT (تغيير IP و/أو Port)، كيف يتعامل الراوتر مع جدول التوجيه والـ TTL، ومتى يظهر دور الـ Switch (forwarding/filtering/flooding). اذكر أيضاً أي رسائل ICMP أو أدوات (مثل traceroute) قد تظهر أثناء المسار ولماذا.

    التقييم (10 درجات): تغطية Network layer (3), Data Link layer & ARP (3), NAT behaviour (2), Transport/Application notes (1), ذكر ICMP/traceroute وأثر TTL (1).
